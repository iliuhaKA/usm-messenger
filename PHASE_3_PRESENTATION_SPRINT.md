## 3. Модель авторизации «логин + пароль» без JWT

### 3.1 Требования

1. Пользователь вводит **логин** (договориться: `email` или отдельное поле `username` — согласовать с колонками в БД) и **пароль**.
2. **POST** на бэкенд → проверка учётных данных.
3. При успехе — фронт получает **безопасный минимум** (например `id`, `firstName`, `lastName`, `email`, `role`) **без пароля**.
4. При неуспехе — **401** и понятное сообщение для показа под формой.
5. Сессия без JWT: допустимые варианты на время презентации (выбрать один):
   - **Вариант A:** фронт кладёт объект пользователя в **Zustand + persist** (`localStorage`), как сейчас задумано для mock-user, плюс флаг «залогинен».
   - **Вариант B:** серверная **HTTP-сессия** (cookie `JSESSIONID`) — больше работы на Spring Security.
   - **Рекомендация для 2 дней:** **Вариант A** + все API по-прежнему с **`userId` в query** или в заголовке кастомном, пока не готов JWT (как временная мера из PHASE_3).

**Важно:** не хранить пароль в `localStorage`. Только данные пользователя и, при необходимости, **серверный session token** (если позже добавят).

```
GET  /api/health
POST /api/auth/login          — body: { "login": "<email sau idnp>", "password": "..." } → 200 UserResponse / 401 { "message" }
GET  /api/users/search?q=    — căutare utilizatori
GET  /api/chats?userId=
GET  /api/chats/{id}?userId=
POST /api/chats?userId=       — body CreateChatRequest
GET  /api/chats/{id}/members?userId=
PATCH /api/chats/{id}/pin?userId=    — body { "pinned": bool }
PATCH /api/chats/{id}/mute?userId=   — body { "muted": bool }
GET  /api/chats/{chatId}/messages?userId=
POST /api/chats/{chatId}/messages?userId= — body { "content": "..." }
POST /api/chats/{chatId}/read?userId=     — пометить чат прочитанным (last_read_at)
```

**WebSocket (STOMP + SockJS):** подключение к `{origin}/ws` (origin = тот же хост, что и API, без `/api`). Топик новых сообщений: `/topic/chats/{chatId}/messages` (тело — JSON `MessageResponse`). Брокер in-memory — один инстанс backend; для кластера нужен RabbitMQ/Redis.
